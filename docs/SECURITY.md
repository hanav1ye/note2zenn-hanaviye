# セキュリティ

## スコープ

note2zenn は **ローカルで動作する VSCode 拡張**です。次をセキュリティ上のスコープとします。

- 本リポジトリのソースコード（TypeScript）
- GitHub Actions ワークフロー（`security_scan.yml` 等）
- 公式ドキュメントに記載された想定どおりの使い方

次は **利用者の運用・環境** に依存するため、脆弱性対応の主対象外とします（[DISCLAIMER.md](DISCLAIMER.md) 参照）。

- VSCode 設定や SecretStorage の誤設定による、意図しないディレクトリへの書き込みや `git push`
- OpenAI 等への記事本文送信に伴う組織ポリシー違反
- API 料金・ディスク容量・処理時間の増大
- 利用者が意図的に渡した URL へのアクセス

## サポートするバージョン

| バージョン | サポート |
|------------|----------|
| リポジトリの default ブランチ（`master`） | 対応 |

タグ付きリリースがない場合、最新の default ブランチを対象とします。

## 脆弱性の報告

セキュリティ上の問題を発見した場合は、**公開 Issue ではなく** 次のいずれかで連絡してください。

- リポジトリの **Security Advisories**（GitHub の「Report a vulnerability」）
- リポジトリ管理者が設定している非公開の連絡先

報告時に含めていただきたい情報:

- 再現手順（API キー等の秘密値はマスクしてよい）
- 影響（例: 意図しないファイル書き込み、シークレットの露出）
- 想定される深刻度と環境（OS、VSCode のバージョン）

## 対応方針

- 内容を確認し、再現可能であれば修正または回避策を検討します
- 重大度が高い場合は、修正が用意できるまでの間、README 等で注意喚起する場合があります
- 対応期限は保証しませんが、可能な範囲で迅速に対応します

## 利用者向けの推奨事項

- `GITHUB_TOKEN` は **最小権限**（対象リポジトリのみ）の fine-grained PAT などに限定する
- 本番の Zenn リポジトリへ push する前に **必ず diff を確認**する
- 社内秘を含む可能性がある原稿を OpenAI API に送信しない
- API キーやトークンは SecretStorage に保存し、平文ファイルに書かない
